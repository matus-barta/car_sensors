# Database migrations and schema synchronization

This document describes how the Car Sensors database schema is managed and how changes are propagated to the SvelteKit web application.

## Architecture

The PostgreSQL schema is owned exclusively by the SQL migration files under:

```text
db/migrations/
```

SQLx is the only migration system used to modify the physical database schema.

The web application uses Drizzle ORM as a type-safe database access layer. Its schema is generated by introspecting a PostgreSQL database to which all SQLx migrations have been applied.

```text
db/migrations/*.sql
        |
        | SQLx applies migrations
        v
PostgreSQL
        |
        | drizzle-kit pull
        v
www/src/lib/server/db/generated/
```

The generated Drizzle schema is a follower of the SQLx-managed PostgreSQL schema. It is not an independent source of database migrations.

## Ownership rules

Developers must follow these rules:

1. Only files under `db/migrations/` may modify the physical database schema.
2. SQLx is the only migration runner.
3. Drizzle is used for schema introspection and type-safe database access.
4. Generated Drizzle schema files must not be edited manually.
5. SQLx migrations and their regenerated Drizzle schema must be committed together.
6. Better Auth database changes must be implemented as SQLx migrations.
7. Drizzle migration metadata and generated SQL must not be used as the project migration history.

Do not run these Drizzle commands against the project database:

```bash
drizzle-kit generate
drizzle-kit migrate
drizzle-kit push
```

These commands would introduce a second migration owner and conflict with the SQLx migration history.

The supported Drizzle database commands are:

```bash
drizzle-kit pull
drizzle-kit studio
```

## Requirements

Database migration and schema synchronization operations require:

- PostgreSQL
- Rust toolchain
- SQLx CLI
- Node.js
- pnpm
- Web dependencies installed under `www/`

Install SQLx CLI with PostgreSQL and Rustls support:

```bash
cargo install sqlx-cli \
    --no-default-features \
    --features rustls,postgres
```

Verify the installation:

```bash
sqlx --version
```

Install the web dependencies:

```bash
cd www
pnpm install
```

## Environment configuration

The migration and synchronization commands require `DATABASE_URL`.

For the default local PostgreSQL deployment:

```bash
export DATABASE_URL="postgres://postgres:postgres@localhost:5432/postgres"
```

If the environment variables are stored in `www/.env`, export them from the repository root:

```bash
set -a
. ./www/.env
set +a
```

The local environment file contains secrets and must not be committed.

## Creating a migration

Create a new SQLx migration from the repository root:

```bash
sqlx migrate add migration-name --source db/migrations
```

For example:

```bash
sqlx migrate add add_vehicle_id --source db/migrations
```

SQLx creates a timestamped migration file similar to:

```text
db/migrations/20260811123000_add_vehicle_id.sql
```

Add the required PostgreSQL statements to the generated file.

For example:

```sql
ALTER TABLE telemetry_samples
    ADD COLUMN vehicle_id TEXT;

CREATE INDEX idx_telemetry_samples_vehicle_id
    ON telemetry_samples(vehicle_id);
```

Migration files are authoritative and must not be edited after they have been applied to a shared or production database.

If an applied migration contains a mistake, create a new migration that corrects it.

## Applying migrations

Apply all pending migrations from the repository root:

```bash
sqlx migrate run --source db/migrations
```

Display the migration state:

```bash
sqlx migrate info --source db/migrations
```

SQLx compares the migration files with the `_sqlx_migrations` table in PostgreSQL and applies pending migrations in order.

The `_sqlx_migrations` table contains internal SQLx state. It is excluded from the generated web schema because the web application does not need to query it.

## Synchronizing the web schema

After adding or changing a migration, regenerate the Drizzle schema used by the web application:

```bash
./tools/sync-ww-db-schema.sh
```

The synchronization script:

1. Verifies that `DATABASE_URL` is configured.
2. Applies all SQLx migrations from `db/migrations/`.
3. Introspects the resulting PostgreSQL schema.
4. Regenerates the Drizzle TypeScript files.
5. Formats the generated TypeScript files.
6. Checks the SvelteKit project.

The complete local workflow is:

```bash
export DATABASE_URL="postgres://postgres:postgres@localhost:5432/postgres"

sqlx migrate add migration-name --source db/migrations

# Edit the generated SQL migration.

./tools/sync-ww-db-schema.sh
```

## Manual schema synchronization

The web schema can also be regenerated directly:

```bash
cd www
pnpm db:sync
```

This command assumes that:

- PostgreSQL is running.
- `DATABASE_URL` is configured.
- All SQLx migrations have already been applied to the selected database.

Running `pnpm db:sync` does not apply SQLx migrations unless the project script explicitly performs that step. It introspects the current database state.

For the complete migration and synchronization workflow, prefer:

```bash
./tools/sync-ww-db-schema.sh
```

## Generated Drizzle files

The following generated files are application build inputs and must be committed when they change:

```text
www/src/lib/server/db/generated/schema.ts
www/src/lib/server/db/generated/relations.ts
```

These files are generated from the PostgreSQL database and must not be edited manually.

The following Drizzle migration artifacts are not used by the project and should remain ignored:

```text
www/src/lib/server/db/generated/meta/
www/src/lib/server/db/generated/*.sql
```

SQLx remains the sole owner of the database migration history.

A normal database change should therefore include:

```text
db/migrations/<timestamp>_<migration-name>.sql
www/src/lib/server/db/generated/schema.ts
www/src/lib/server/db/generated/relations.ts
```

Review the generated changes before committing them:

```bash
git diff -- \
    db/migrations \
    www/src/lib/server/db/generated/schema.ts \
    www/src/lib/server/db/generated/relations.ts
```

Stage the migration and generated schema:

```bash
git add db/migrations
git add www/src/lib/server/db/generated/schema.ts
git add www/src/lib/server/db/generated/relations.ts
```
