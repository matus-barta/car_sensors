title: "Refresh the time zone centres at release"

When no vehicle has a position yet, the map opens on the location of the
browser's time zone (`getDefaultView()` in `www/src/lib/map/default-view.ts`),
and the coordinates come from
`www/src/lib/map/generated/timezone-centers.json`. That file is generated by
`tools/scripts/generate-timezone-centers.js` from IANA's `zone.tab`, and
committed - deliberately, so building `www` needs no network access and gives the
same result every time. It records which tzdata release it came from: `"tzdata":
"2026d"`.

Nothing checks it afterwards. Unlike the other generated files - the Drizzle
schema, `docs/schema/`, `openapi.json` - it is not regenerated in CI, and it
should not be on every build: the script downloads `tzdata-latest`, so a build
would change whenever IANA publishes, for reasons that have nothing to do with
the change being built. tzdata releases come a few times a year and seldom move
a zone anyone opens the map from, so an old file is a small cost; it only needs
refreshing now and then, by a person who looks at the diff.

The right moment is a release of `www`. The check to run then is cheap and
decides nothing on its own: download `tzdata-latest`, read its `version` file,
and compare it with the `tzdata` field in the committed JSON. If they differ,
say so - the person releasing runs the script, reviews the diff and commits it.
Whether a stale file should block the release or only warn is worth deciding
when the step is written; a warning is probably enough.

**What is missing first: `www` has no release.** `www-build.yml` publishes the
image on every push to `main`, so there is no moment to hang this on yet. Until
there is, a `workflow_dispatch` workflow - run by hand, comparing the versions
and, if they differ, regenerating the file and opening a pull request with it -
would make the refresh one click instead of something to remember the command
for.

When this lands, update [`docs/ci.md`](../ci.md#generated-output-is-checked-where-it-belongs),
which names this file as the one generated output not compared in CI.
